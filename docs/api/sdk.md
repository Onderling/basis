# `@onderling/sdk` — API reference

> Generated by `node scripts/api-appendix.mjs` from the exported surface and source JSDoc.
> Do not edit by hand — edit the JSDoc in the source and regenerate. `npm run api-fitness` fails on drift.

Batteries-included, LAYERED developer facade for @onderling. ONE import for the whole SDK. LOW layer: named re-exports of the kernel (@onderling/core) plus the default adapters (VaultMemory + Vault family from @onderling/vault, the transports from @onderling/transports, the pod pieces from @onderling/pod-client) — a dev wires adapters explicitly for maximal clarity + compatibility. HIGH layer: thin opinionated helpers built ON the low layer — createAgent({...}) (run-as-agent, Tier 3, injects the defaults) + connectSkill(agent, name, appFn) (Tier 1: map any plain app function to a skill). Purely additive; the kernel stays de-fatted (defaults live HERE, not in core).

## `src/buildSkillsFromManifest.js`

### `buildSkillsFromManifest`

**Kind:** function · **Import:** `buildSkillsFromManifest` from `'@onderling/sdk'`, `'@onderling/sdk/high'`, `'@onderling/sdk/skills'`

```js
buildSkillsFromManifest({ operations, cores, storeFor, requireCore = true, visibilityFor, label = 'buildSkillsFromManifest', } = {})
```

The shared manifest-op → core → `wireSkill` loop: for each op in `operations`, look its core up
in `cores`, wrap it with `wireSkill(core, op, { storeFor })`, and emit `{ id, handler,
visibility }` for the caller to `agent.register`. Zero-node module; op selection and ordering are
the caller's job — pass `operations` already narrowed to exactly the ops to wire.

**Parameters**

- `args` `object`
- `args.operations` `Array<object>` — the manifest ops to wire, already filtered/ordered.
- `args.cores` `Record<string, Function>` — `{ opId: coreFn }` pure cores.
- `args.storeFor` `(ctx: object) => any` — resolves the scope store (passed to `wireSkill`).
- `[args.requireCore=true]` `boolean` — throw when an op has no core (the anti-drift guard); when false, coreless ops are skipped.
- `[args.visibilityFor]` `(op: object) => (string|undefined)` — per-op visibility resolver; defaults to the op's own `op.visibility`.

### `validateRequires`

**Kind:** function · **Import:** `validateRequires` from `'@onderling/sdk'`, `'@onderling/sdk/requires'`

```js
validateRequires(requires, { available } = {})
```

Validate an app's declared `requires` against the capability vocabulary
and (optionally) the wired/available set.

Semantics:
  1. UNKNOWN — any requested capability not in {@link CAPABILITIES} is
     reported in `unknown` with code {@link REQUIRES_CODES.UNKNOWN}.
  2. MISSING — when an `available` set is supplied, any KNOWN requested
     capability not in it is reported in `missing` with code
     {@link REQUIRES_CODES.MISSING}. An unknown capability is only ever
     reported as `unknown`, never also as `missing`.
  3. `ok` is true iff both lists are empty.

If `available` is omitted, only the vocabulary check runs (nothing can be
`missing`). Order and duplicates in `requires` are preserved in the output.

**Parameters**

- `requires` `ReadonlyArray<string>` — the app's declared capability list
- `[opts]` `object`
- `[opts.available]` `ReadonlyArray<string>` — the wired/present slices; omit to skip the presence check.

**Returns:** `RequiresResult`

## `src/wireSkill.js`

### `wireSkill`

**Kind:** function · **Import:** `wireSkill` from `'@onderling/sdk'`, `'@onderling/sdk/high'`

```js
wireSkill(coreFn, op, { storeFor } = {})
```

Generate a `defineSkill`-shaped handler from a manifest op declaration. The handler decodes
`ctx.parts` into named args (connectSkill's `decodeArgs`; a lone TextPart binds to the op's first
param), validates them against `op.params` (required-ness + per-kind string/number/boolean/enum
checks; unknown kinds pass through), resolves the scope store via `storeFor(ctx)`, and returns
`coreFn(store, args, ctx)` unchanged. Validation failures throw.

**Parameters**

- `coreFn` `(store: any, args: object, ctx: object) => any` — the scope-bound core function.
- `op` `object` — a manifest Operation declaration `{ id, verb?, params?, visibility?, … }`.
- `deps` `{ storeFor: (ctx: object) => any }` — `storeFor` resolves the store per invocation.

**Returns:** `(ctx: object) => any` — the handler to register under `op.id`.
